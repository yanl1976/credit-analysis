# 合作方资信分析系统 · 技术开发规范

> 本规范为项目开发纪律，所有开发活动必须遵守。

## 1. 项目边界（铁律）
- 本项目为**独立工程**，所有代码、配置、文档、临时文件**仅限** `e:/tedri_project/dev/Credit Analysis/` 目录内。
- **严禁**读取、修改、删除其他项目（如 `Plm_Code`、`safety`、`skydra_erp_agent`、`stock-analysis-pro` 等）的任何文件；即使复用思路，也只在本目录内新建文件。
- 依赖安装（`npm install`）、构建、运行命令均限定在本目录，不得影响其他项目的 `node_modules` / 构建产物。

## 2. 版本控制节奏
- 每完成一个**小计划**（章节内编号项，如 1.1 / 1.2）即执行本地 `git commit`（中文 UTF-8 说明，用 `.gitmsg.tmp` 临时文件承载避免乱码，提交后删除）。
- **push 由用户手动执行**（开发机网络不稳定）：开发者只负责本地 `commit`，**绝不主动 `git push`**。
- 每个**大计划**（章节）完成后，必须进行全面功能测试并修复 BUG，修复也本地 `commit`；所有提交待用户自行 `push`。
- 提交说明清晰标注计划编号与范围，例如 `feat: 配置层（1.2）`、`fix: 评分空数据导致崩溃（5.2）`。
- 不在主分支之外随意建分支；修复直接在主分支提交。

## 3. 功能测试（每个大计划完成后，必须执行）
- 大计划代码完成后**必须进行全面功能测试**，不得"写完即交付"。
- 测试范围至少覆盖本章节所有新增模块 / 接口 / 页面：
  - **正常路径**（happy path）；
  - **边界与异常**：空值、无权限、渠道未配置、重复数据、错误输入、网络/外部接口缺失；
  - **跨模块契约**：上游输出是否被正确下游消费。
- 测试方法：Node 内置 http 自测脚本 / 接口调用校验 / 前端手动验证。临时测试脚本**用完即删**，结尾 `process.exit(0)` 避免连接池保活导致进程挂起。
- **通过标准**：本章节核心用例 100% 通过，无未修复的致命 / 严重 BUG。
- 发现 BUG：**及时修复** → 修复后**回归测试**受影响模块 → 确认无误再提交。

## 4. 业务逻辑前后校验（贯穿全程，每个大计划交付前必做）
- 校验本章节与**上游数据模型**和**下游消费方**的业务逻辑一致性：
  - 数据模型 → 采集：采集落库的字段 / 口径必须与 `partner_*` 表定义一致；
  - 采集 → 评分：评分引擎消费的数据（司法 / 信用 / 财务）必须来自采集落库结果，口径不脱节；
  - 评分 → API / 前端：API 返回与前端展示的字段契约一致（评分明细 `reasons` 结构统一）；
  - 权限：数据作用域（`owner_org_id` + `path`）必须贯穿所有涉及 `partner` 的查询，前后一致。
- 跨章节"方案口径"一致性：评分权重、否决规则、等级映射须与 `docs/技术方案.md` 第五章一致，改动须同步文档。
- 任何破坏前后业务一致性的改动，视为 BUG，按第 3 节流程修复。

## 5. 临时脚本与调试
- 临时调试 / 测试脚本放本目录，结尾 `process.exit(0)`（避免 Knex 连接池保活导致进程挂起）。
- 用完即删，不入库（或已被 `.gitignore` 忽略）。
- 不向其他项目目录写入任何临时文件。

## 6. BUG 修复流程
1. 复现并定位（必要时写最小复现脚本）；
2. 修复，附回归测试；
3. 本地 `commit`（说明 `fix: ...`）；
4. 大计划测试阶段统一 `push`。
